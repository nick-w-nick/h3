# Router

> Split your application using routes.

Using the h3 router allows for a more advanced and convenient routing system with functionality for dynamic URL parameters and customizable routing, while the [app instance](/guide/app) itself only allows static path prefix matching.

> [!NOTE]
> Internally h3 uses [unjs/radix3](https://radix3.unjs.io) for route matching.

## Usage

First, you need to create a router using the `createRouter` utility and register it to the application stack using the `app.use()` method.

```ts
import { createApp, createRouter } from "h3";

const app = createApp();
const router = createRouter();
app.use(router);
```

Then, you can register an event handler to the specified route by providing the route path and the event handler callback.

```ts
router.get("/hello", () => "Hello world!");
```

In this example, we register a route for the `GET` HTTP method via the `router.get` method. This means that the event handler will be called only for `GET` requests to the `/hello` path. Other HTTP methods will not be handled and will return a 404 status response.

> [!NOTE]
> You can also utilize the `router.use()` method to register an event handler to the router, but it will not be limited to a specific HTTP method and will accept any incoming calls to the route.

A bonus of the router is that you can register multiple event handlers for the same route by chaining the individual HTTP methods to represent the desired behavior for each method.

```ts
router
  .get("/hello", () => "GET Hello world!")
  .post("/hello", () => "POST Hello world!");
```

## Route Path Parameters

You can define dyamic route path parameters in your routes using the `:` prefix, which will represent the name of the key where the parameter value will be stored in the `event.context.params` object:

```ts
router.get("/hello/:name", (event) => {
  return `Hello ${event.context.params.name}!`;
});
```

In this example, the value from the `name` path parameter will be available in the `event.context.params` object via the `event.context.params.name` property. This means a request to `/hello/world` in the code above will return `Hello world!` as the response.

## Wildcard matcher

You can also use a wildcard matcher to match multiple routes using the `*` prefix:

```ts
router.get("/hello/*", (event) => `Hello ${event.context.params._}!`);
```

This will match both `/hello` and sub routes such as `/hello/world` or `/hello/123`.

> [!NOTE]
> This will match only one level of sub routes, meaning a request to `/hello/world/123` will not be matched.

The content of the URL parameters captured by the wildcard are stored and can be accced via the `event.context.params._` property, where `_` is a string containing the matched content.

If you need to match multiple levels of sub routes, you can use `**` prefix:

```ts
router.get("/hello/**", (event) => `Hello ${event.context.params._}!`);
```

This will match `/hello`, `/hello/world`, `/hello/123`, `/hello/world/123`, etc.

> [!NOTE]
> The `_` parameter will store the full wildcard content as a single string. (ex: a request to `/hello/world/123` will contain `world/123` in the `_` parameter).
> 
> A request to `/hello` will contain an empty string in the `_` parameter.

## Nested Routers

You can nest routers to create a tree of routers. This is useful to split your application into multiple parts like the API and the website.

```ts
import { createApp, createRouter, useBase } from "h3";

export const app = createApp();

const websiteRouter = createRouter().get("/", () => "Hello world!");

const apiRouter = createRouter().get("/hello", () => "Hello API!");

websiteRouter.use("/api/**", useBase("/api", apiRouter.handler));

app.use(websiteRouter);
```

We create two routers. The first one, called `websiteRouter` is the main one. The second one, we create a second router called `apiRouter`.

Then, we connect the `apiRouter` to the `websiteRouter` using `use` and a wildcard to be sure that every routes starting and HTTP methods with `/api` will be handled by the `apiRouter`.

> [!NOTE]
> Do not forget to use `.handler` to get the event handler from the router.

`useBase` is used to add a prefix to each routes of the router. In this example, we add `/api` prefix to each routes of the `apiRouter`. So, the route `/hello` will be `/api/hello`.

Finally, we register the `websiteRouter` to the `app` instance.
