# Event Handler

> Event handler defines application logic.

After creating an h3 [app instance](/guide/app), you can start defining your application logic using event handlers.

An event handler is a function that receive an `Event` instance and returns a response. You can compare it to controllers in other frameworks.

## Defining event handlers

You can define typed event handlers using `defineEventHandler`:

```ts
import { defineEventHandler } from "h3";

defineEventHandler(() => "Response");
```

The callback function provided to the event handler can be sync or async:

```ts
defineEventHandler(async () => "Response");
```

### Object syntax

You can provide the individual configuration options directly in `defineEventHandler` if preferred:

```ts
defineEventHandler({
  onRequest: [], // can be a single event handler or an array of event handlers
  onBeforeResponse: [] // can be a single event handler or an array of event handlers
  handler: () => "Response",
})
```

## Response Types

Values returned from event handlers are automatically converted to responses. These values can be of the following types:

- JSON serializable value. If returning a JSON object or serializable value, it will be stringified and sent with default `application/json` content-type.
- `string`: Sent as-is using default `text/html` content-type.
- `null`: Returns an empty response with a `204 - No Content` status code.
- `undefined`: Returns a `404 - Not Found` status response.
- [Web `ReadableStream`](https://developer.mozilla.org/en-US/docs/Web/API/ReadableStream) or [node `Readable`](https://nodejs.org/api/stream.html#readable-streams)
- [Web `ArrayBuffer`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/ArrayBuffer) or [node `Buffer`](https://nodejs.org/api/buffer.html#buffer)
- [Web Fetch Response](https://developer.mozilla.org/en-US/docs/Web/API/Response/Response)
- [`Error`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Error) instance. Although they are supported, it is **recommended** to throw errors using the [`createError`](#error-handling) utility.

Any of above values could also be wrapped in a [`Promise`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise). This means that you can return a `Promise` from your event handler and h3 will wait for it to resolve before sending the response.

**Example:** Returning an HTML response:

```ts
app.use("/hello", defineEventHandler({
  handler: (event) => {
    event.response.headers.set("Content-Type", "text/html");
    return "<h1>Hello world!</h1>";
  },
}));
```

**Example:** Returning a JSON response:

```ts
app.use("/hello", defineEventHandler({
  handler: (_event) => {
    // h3 automatically sets the Content-Type to application/json when returning valid JSON
    return {
        message: "Hello world!",
    };
  },
}));
```

**Example:** Responding with a `Promise`:

```ts
app.use("/hello", defineEventHandler(async (_event) => {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve({ message: "Hello world!" });
    }, 1000);
  });
}));
```
> [!TIP]
> The response will be sent once the promise has been resolved and will contain the resolved value. If the promise is rejected, h3 will automatically handle the error and send a `500 - Internal Server Error` status response.

## Error Handling

You can easily control the structure of the error returned by using the `createError` utility.

```ts
import { createError, defineEventHandler } from "h3";

app.use(
  "/validate",
  defineEventHandler((_event) => {
    const CustomError = createError({
      status: 400,
      statusMessage: "Bad Request",
      message: "Invalid user input",
      data: { field: "email" },
    });
    
    throw CustomError;
  }),
);
```

This will end the request with a `400 - Bad Request` status code and the following JSON response:

```tson
{
  "statusCode": 400,
  "statusMessage": "Bad Request",
  "stack": [],
  "data": {
    "field": "email"
  }
}
```

### String vs. Object Errors

When creating an error using `createError`, you also have the option to pass a string instead of an object as the parameter. Doing so will set the `message` property of the error to the string provided. In this case, the `statusCode` will default to `500`.

```ts
import { createError, defineEventHandler } from "h3";

app.use(
  "/hello",
  defineEventHandler((_event) => {
    throw createError("An error occurred");
  }),
);
```

> [!TIP]
> Typically, `message` contains a brief, human-readable description of the error, while `statusMessage` is specific to HTTP responses and describes the status text related to the response status code.
> In a client-server context, using a short `statusMessage` is recommended because it can be accessed on the client side. Otherwise, a `message` passed to `createError` on the server will not propagate to the client (you can use `data` instead). Consider avoiding using dynamic user input in the error message to avoid potential security issues.

### Internal errors

If an error that was not thrown by `createError` occurs, h3 will automatically catch it and will respond with a [`500 - Internal Server Error`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Status/500) status code.

```ts
app.use(
  "/hello",
  defineEventHandler((_event) => {
    throw new Error("Something went wrong");
  }),
);
```

## Lazy event handlers

You can define lazy event handlers using `defineLazyEventHandler` or `lazyEventHandler` utilities. This allows you to define one-time logic that will be executed only once when the first request matching the route is received.

A lazy event handler must return an event handler:

```ts
import { defineLazyEventHandler } from "h3";

app.use(
  defineLazyEventHandler((_event) => {
    console.log("This will be executed only once");
    // This will be executed only once
    return defineEventHandler((_event) => {
      // This will be executed on every request
      return "Response";
    });
  }),
);
```

This is useful to define one-time logic such as configuration, class initialization, heavy computation, etc.

## Middleware

Event handlers that don't return any value act as middleware. They can be used to add side effects to your application such as logging, caching, etc. or to modify the request or response.

Similar to normal event handlers, you can define middleware using the `defineEventHandler` utility:

```ts
app.use(
  defineEventHandler((event) => {
    console.log(`Middleware Path: ${event.path}`);
  });
);
```

> [!IMPORTANT]
> Middleware **must not** return any value or directly return a response.
> If you return a response, it will act as a normal event handler and will end the request using the return value as the response

### Registering middleware

You can register middleware to [app instance](/guide/app) using the `use` method with the event handler as the first argument:

```ts
app.use(
  defineEventHandler((event) => {
    console.log("Middleware 1");
  }),
);
app.use(
  defineEventHandler((event) => {
    console.log("Middleware 2");
  }),
);
app.use(defineEventHandler(() => "Response"));
```

> [!TIP]
> Middleware will be executed in the order they are registered in the code.

## Converting to an h3 handler

There are situations where you may want to convert an existing event handler, Node.js utility, or another framework to h3.

Luckily, there are utilities built into h3 to help provide a seamless transition for a majority of use cases.

### Converting from Node.js handlers

If you have a legacy request handler which uses the traditional `(req, res) => {}` structure typically used in Node.js, you can use the `fromNodeHandler` utility to convert it to an h3 event handler.

```ts
import { createH3, fromNodeHandler } from "h3";

import exampleMiddleware from "example-node-middleware";

export const app = createH3();

app.use(fromNodeHandler(exampleMiddleware()));
```

> [!TIP]
> See here for using [Vite Middleware mode](https://vitejs.dev/config/server-options.html#server-middlewaremode) with h3 apps.

### Converting from Web handlers

You can convert a fetch-like function (with `Request => Response` signature) into an h3 event handler using the `fromWebHandler` utility.

```ts
import { createH3, fromWebHandler } from "h3";

const webHandler = async (request) => {
  const url = new URL(request.url);
  if (url.pathname === "/hello") {
    return new Response("Hello, world!", { status: 200 });
  } else {
    return new Response("Not Found", { status: 404 });
  }
};

export const app = createH3();

app.use(fromWebHandler(webHandler));
```
