# App Instance

The h3 app instance is the core of the server that handles incoming requests. It is responsible for routing, request and response parsing, and processing [lifecycle hooks](#lifecycle-hooks).

## Initializing an app

You can create a new h3 app instance using the `createH3` utility:

```js [app.mjs]
import { createH3 } from "h3";

const app = createH3();
```

## Setting global options

You can pass global app configuration when initializing an h3 application.

**Example:** Creating an h3 app with verbose logging enabled:

```js
const app = createH3({
  debug: true,
});
```

## Lifecycle hooks

When initializing an h3 app, there are a number of lifecycle hooks that can be registered globally:

- `onError`
  - Called when an error occurs in an event handler.
- `onRequest`
  - Called before an event handler is called.
- `onBeforeResponse`
  - Called before a response is sent.
- `onAfterResponse`
  - Called after a response is sent.

These hooks are set globally and thus are called for every request and can be used to add global logic to your app such as logging, error handling, and more.

```js
const app = createH3({
  onError: (error) => {
    console.error(error);
  },
  onRequest: (event) => {
    console.log("Request Path:", event.path);
  },
});
```

## Registering event handlers

You can register [event handlers](/guide/event-handler) to your app instance using a number of ways. The most common way is to use the method to represent the specific HTTP method you'd like your event handler to respond to:

```ts
app.get("/", defineEventHandler((_event) => {
  return {
    message: "⚡️ Tadaa!",
  };
}));
```

Another way is to use the `use` method to register an event handler to the app instance, where the event handler will be called for every request to the specified route, regardless of the HTTP method:

```ts
app.use("/", defineEventHandler((_event) => {
  return {
    message: "⚡️ Tadaa!",
  };
}));
```

You can define multiple event handlers for the same route. h3 will try to to call them one by one in order of registration until one of them returns a valid response. This is called a `stack runner`.

```js
app.use("/hello", () => "First");
app.use("/hello", () => "Second");
```

In this example, the first event handler will be called for every request to the `/hello` path, but the second one will never be called, since the first one already returns a valid response.

However, if you do not return a response from the first event handler, the second one will be called. This is useful for middleware-like event handlers, where you need to perform some processing on the request before passing it to the main event handler that returns the response. This is commonly used for things like logging, authentication, and more.

```js
app.use("/", () => {
  console.log("First");
  // No response returned
});
app.use("/", () => "Second");
```

If all handlers get called and no response is returned, h3 will end the request with `404` status response.

> [!NOTE]
> Returning `undefined` will produce a [`404 Not Found`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Status/404) status response.
> Returning `null` will produce a [`204 No Content`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Status/204) status response.

> [!TIP]
> Return any non-undefined value (see [Response Types](/guide/event-handler#response-types)) to produce a [`200 OK`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Status/200) status response by default.

## Event handler options

The `use` method accepts an optional `options` object as a third argument:

```js
app.use("/hello", () => "Hello world!", {
  // Options
});
```

The following options are available:

### `handler`

### `method`

### `route`
